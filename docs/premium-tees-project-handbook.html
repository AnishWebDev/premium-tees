1. Project overview

Premium Tees is a production-oriented apparel e-commerce app focused on the Indian market (INR, Razorpay). It includes a public storefront, customer accounts, and a role-gated admin CMS for catalog, orders, returns, content, and visual style.

What it sells

Premium t-shirts / apparel with variants (size, color), inventory, reviews, wishlist, and coupons.

What makes it configurable

CMS JSON content, theme presets, and SuperAdmin-selectable homepage templates that reuse shared blocks.

3. Local & production setup

Local

cp .env.example .env
# fill DATABASE_URL, AUTH_SECRET, and either Razorpay test keys or DEMO_CHECKOUT=true
npm install
npm run db:push
npm run db:seed
npm run dev

Production (Vercel)

  1. Connect the GitHub repo to Vercel.
  2. Set all required env vars (see §4). Use live Razorpay keys for real customers.
  3. Set DEMO_CHECKOUT=false and NEXT_PUBLIC_DEMO_CHECKOUT=false.
  4. Run schema push + seed once against production Postgres if empty.
  5. Configure Razorpay webhook → https://your-domain.com/api/webhooks/razorpay (event: payment.captured).
  6. Verify Resend sender domain for invoices.

One-time price conversion

If seeded prices still look USD-like (~38–85), run:

DATABASE_URL="..." npx tsx scripts/convert-prices-to-inr.ts

8. Checkout, payments & fulfillment

Flow

  1. Client posts cart to POST /api/checkout.
  2. Server creates Order with status PENDING, currency inr.
  3. Demo path: if DEMO_CHECKOUT=true and Razorpay keys missing → invent demo payment IDs, call fulfillOrder, redirect to success.
  4. Live path: create Razorpay order (paise), return key + order id to Checkout.js.
  5. Client verifies signature via /api/checkout/verify → fulfillOrder.
  6. Webhook payment.captured is a backup fulfillment path.

Key files

  • src/lib/razorpay.ts
  • src/lib/fulfill-order.ts — mark PAID, decrement inventory, coupon use, invoice email
  • src/components/checkout/checkout-form.tsx
  • src/app/api/checkout/, src/app/api/webhooks/razorpay/

Ops after payment

  • Packing slip: Admin → Orders → Pack / print page
  • Shipped email: set status Shipped + carrier/tracking
  • Returns: customer requests from order detail; admin reviews at /admin/returns

11. Theme system

Files: src/lib/theme.ts, src/components/theme/theme-style.tsx, src/components/admin/theme-editor.tsx, src/lib/fonts.ts.

Theme writes CSS variables (--background, --foreground, button/link vars, font families).

Presets

studio, editorial, slate, olive, noir, ink-gold

Editable fields

  • Colors: background, foreground, muted, border, accent, ring
  • Fonts: sans + display (from FONT_CATALOG)
  • Buttons: radius (pill/rounded/square), style (solid/outline/soft), weight
  • Links: underline / accent / subtle / bold
Theme affects the whole storefront chrome. Homepage templates change layout/density, not necessarily the color preset (unless you also change Theme).

How to switch template

  1. Sign in as SuperAdmin.
  2. Go to Admin → Site content → Home.
  3. Pick a template card (shows density + inspiration).
  4. Save content.

How to add a new template

  1. Add id to HOME_TEMPLATE_IDS and metadata in src/lib/home-templates.ts.
  2. Create src/components/home/templates/your-home.tsx accepting HomeTemplateProps.
  3. Register it in src/components/home/templates/index.tsx.
  4. Reuse blocks from src/components/home/blocks/ and effects from src/components/effects/.
  5. Keep a11y: headings, focus rings, contrast overlays, reduced motion.

18. Accessibility & Lighthouse guidelines

Applied especially to homepage templates / effects. Follow these when adding UI:

  • One clear h1 per page; nest h2/h3 logically.
  • Interactive elements need visible focus rings (focus-visible:ring-…).
  • Text on imagery needs dark overlays; prefer ~white/90 on dark scrims.
  • Decorative images: alt="" when adjacent text already names the content.
  • Respect prefers-reduced-motion (carousel autoplay off, video → poster, marquee animation off).
  • Limit priority images (usually hero + 1 product) to protect LCP.
  • Regions: use aria-label / aria-labelledby on carousels, shelves, nav groups.
  • Don’t hide essential CTAs behind hover-only styles (touch + SR users).

20. How-to recipes (common edits)

A. Change homepage hero image / headline

  1. Admin → Site content → Hero
  2. Update image URL (and optional video URL)
  3. Edit headline / CTAs → Save

B. Change which products appear on home

  1. Admin → Products → edit flags: Featured / Best seller / New arrival
  2. Homepage queries these flags (getFeaturedProducts, getBestSellers, getNewArrivals)

C. Add a new home block and use it in Commerce

  1. Create src/components/home/blocks/my-block.tsx
  2. Import into commerce-home.tsx and place in JSX
  3. If copy is needed, extend HomeData in site-content.ts + admin editor fields

D. Add a theme preset

  1. Append to THEME_PRESETS in src/lib/theme.ts
  2. It appears automatically in the theme editor

E. Add an admin-only page

  1. Add route under src/app/(admin)/admin/…
  2. Link it in src/components/admin/admin-sidebar.tsx
  3. Protect mutations with requireAdmin() / requireSuperAdmin()

F. Go live checklist

  1. DEMO_CHECKOUT=false, public demo flag false
  2. Live Razorpay keys + webhook secret
  3. Resend configured; send a test order
  4. AUTH_URL / NEXT_PUBLIC_APP_URL match domain
  5. Change seeded admin passwords
  6. Smoke-test: shop → checkout → verify → packing slip → ship → return
